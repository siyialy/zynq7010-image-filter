# 叶片病斑人工标注工具

本工具使用程序实际输入的 24 张 256×256 RGB 图片。现有 65 个检测候选仅作待确认初稿，不会自动成为真值。工具不连接板卡，不修改 PS/PL 程序，也不向外部服务器传图片。

## 开始操作

1. 双击项目根目录的 **打开病斑标注工具.cmd**，或在系统浏览器中打开本目录 `index.html`。请保留完整的 `annotation_tool` 文件夹，不能只复制 HTML。
2. 默认显示第 14 张。左侧选图片，上方“上一张 / 下一张”或左右方向键切换。右侧内容较多时可单独向下滚动。
3. **检查橙色虚线候选**：正确的点“接受”；错误的点“排除”；无法判断的点选候选后选“不确定”。也可标为“背景 / 非病斑”。
4. **检查没有候选的位置**：点“新增框”，选“病斑”，在图片上拖出矩形。圈住整处病斑并贴近边界，不只圈最黑的中心，也不要包含大片正常叶片。
5. **修正框**：点“选择 / 调整”，点击绿色人工框后拖动框体，或拖四角缩放。小框可按住 Alt 拖动；也可直接填写右侧 X、Y、宽、高，再点“应用精确坐标”。用“放大 2 倍 / 4 倍”检查细小区域，滚动查看放大后的画布。
6. Delete 删除选中的人工框；“撤销”或 Ctrl+Z 回退最近操作。接受后的框也应检查边界，不要因为它来自算法就直接当作正确答案。
7. 检查整张图，处理完全部候选后，点右侧最下方“标记本张审核完成”。没有病斑框的图片，需要明确勾选“我已检查整张图，未标出可靠病斑”。后续改框会自动取消完成状态，需再次确认。
8. 随时点右上角 **导出标注 JSON**。未审核图片也会作为草稿导出；它们不会计入定位评估。之后用“导入标注”恢复。

## 标注类别

| 显示 | 含义 | 评估时如何处理 |
|---|---|---|
| 橙色虚线 | 算法候选，尚未人工确认 | 不是病斑真值 |
| 绿色实线 | 人工确认的病斑 | 作为真值，与预测一对一匹配 |
| 紫色 | 图像模糊、遮挡等原因，确实无法判断 | 单独记录；落在其中的未匹配预测可被排除并单独报告 |
| 蓝色 | 已确认背景、叶脉、阴影或其他非病斑 | 不作为病斑真值；算法在这里出框仍计误框，不会被忽略 |

一处明显独立的病斑一个框；明显分离的病斑分开标。相连区域的划分规则应在全部图片中保持一致。不要把所有深色区域都当作病斑；无法确认时保留“不确定”，必要时参照比赛提供的标签或请熟悉病害的人复核。

“未标出可靠病斑”仅表示这一张没有人工确认框，不等于证明叶片健康。不要将已知背景误框标为“不确定”来提高指标。

## 保存位置与备份

- 页面会尝试把草稿存到当前浏览器的本地存储，并显示保存状态。
- 浏览器草稿不是独立文件。换浏览器、清理缓存、移动工具路径或使用隐私窗口，可能无法找到之前的草稿。
- **每完成几张就导出一次 JSON**，建议保存到 `D:/FPGA比赛/annotation_tool/人工标注备份/`，保留导出时间。
- 导入会校验图片编号、RGB 哈希、尺寸和坐标，图片集不匹配时拒绝覆盖。
- 不要把 `dataset.json` 当作人工标注；它只有图片及候选元数据。真正标注文件由页面“导出标注 JSON”生成。

## 生成漏检和误框报告

将你导出的 JSON 文件拖到项目根目录 **评估病斑标注.cmd** 图标上。它会在 `annotation_tool/reports/` 下生成：

- `evaluation.md`：可读的逐图指标表。
- `evaluation.json`：每图 TP / FP / FN、漏掉的真值编号、错误候选编号和配对 IoU。

也可以运行：

```powershell
python tools/evaluate_annotations.py --annotations "你的标注文件.json"
```

默认 IoU 门限为 0.5。程序采用一对一匹配；重复框按误框处理。只有人工审核完成的图片参与评估，其他图片跳过；没有任何审核完成图片时，不会给出虚假的精度数字。

报告同时给出两种范围：

1. **源图候选区域**：256×256 图片中的候选连通域框，不含显示外扩边距。
2. **HDMI 显示框投影**：使用 PL 实际输出的显示坐标，并把人工真值投影到同一显示坐标，包含当前红框外扩边距的影响。

两种指标应分别看，不能混用。小病斑对一两像素偏移很敏感。JSON 另给出面积小于 64 源像素的小病斑召回率及因“不确定”而排除的预测数量。

现有 24 张已反复用于调参，是**开发集**。本工具不会把它们变成独立测试集。后续需要另收集未参与调参的新图片，按叶片/植株来源分组，避免同一片叶子的相似照片跨组。

## 文件与检查

- `images/`：与固件输入逐字节一致的 RGB PNG。
- `dataset.json` / `dataset.js`：图片身份、源坐标候选及 PL 显示框，不含人工真值。
- `app.js` / `model.js`：页面交互和标注格式校验。
- 坐标格式为原图整数 `xyxy_half_open`，左上边界包含、右下边界不包含；1×1 像素框面积为 1。右侧直接显示 X、Y、宽、高，无需手算边界。

开发检查：`node tools/test_annotation_tool.js`、`python tools/test_annotation_evaluation.py`。它们检查坐标/事件流程、导入身份、一对一匹配、未审核排除、不确定区域与背景误框处理。

内置浏览器拒绝本地 `file` 协议，因此本次未完成真实浏览器渲染和鼠标设备验收。页面逻辑通过 Node DOM 替身检查；该检查不等于浏览器实机预览。
