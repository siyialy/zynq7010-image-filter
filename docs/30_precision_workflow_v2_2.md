# v2.2 全流程检查与定位改进

当前默认运行版已更新为 [v2.3 第 14 张定位改进版](31_sample14_localization_v2_3.md)，本文保留 v2.2 作为流程说明及回退记录。

## 用户反馈与检查范围

本次重点：20 右侧背景误框；19 左边缘漏框；17 中央、上方、左边漏框；16 最上方漏框；14 部分病斑漏框。固定使用现有 24 张嵌入样本，前 12 张健康、后 12 张有病害，不更换顺序或标签。检测规则不读取样本编号或标签。

## 当前真实数据流程

1. 电脑通过 JTAG 初始化 Zynq PS/DDR，下载 PL bitstream 与 PS ARM ELF。
2. 24 张 256×256 RGB 图片已编译进 ELF，在板卡 DDR 内。切图时无需由电脑重新发送一张图片；串口只发送控制按键和读取结果。
3. PS 的 C 程序对 RGB 做 3×3 均值预处理，经 AXI 寄存器上传 PL。颜色保留给检测使用。
4. PL 用 Verilog 完成叶片区域提取、局部对比度计算、候选提取、形态学、连通域、组织证据、去重与排序，产生最多 16 个框。PS 只读回结果与统计，不在本次运行路径中做病斑识别。
5. PS 单独生成去噪灰度显示图：中值、保边平滑、双线性缩放和柔和侧背景。显示去噪不会覆盖检测使用的颜色。
6. 显示图传入 PL 图像缓冲；框经跨时钟域提交，在帧边界更新。PL 像素流水线画红框并由 HDMI 输出。

GE-PS 网口传图、SD/Flash 独立启动尚未在本次实现。当前断电重启仍需要运行电脑端启动脚本。

## 本次发现与修改

| 原流程问题 | v2.2 修改 | 意义及限制 |
|---|---|---|
| 只显示源图 y=32..223，检测也拒绝裁剪区外候选 | 保留完整 256×256，以 240×240 等比放进 320×240 显示画布，左右柔和背景 | 上下边缘病斑不再因裁图直接丢弃；保留比例，叶片显示宽度会比原先裁图方案小 |
| 叶片色彩种子可能包含离散背景 | 闭运算后保留最大叶片连通区域、填孔；保留边缘，取消内部腐蚀 | 减少离散背景候选，但贴着叶片的阴影仍需颜色及组织证据过滤 |
| 病斑颜色范围较窄 | 添加暗橄榄色核心及受约束的弱候选 | 扩大部分深色/褪色病斑召回；不对所有暗像素直接画框 |
| 单看暗度/对比度会接纳背景阴影 | 检查核心占比、周围组织、绿色与病斑色环带；新颜色候选有额外证据要求 | 抑制背景误框，仍有低对比度及极暗病斑漏检的取舍 |
| 最多 8 个框，病斑多时被挤掉 | PL、读回协议、总线、跨时钟域与画框同步扩到 16 个 | 只提高容量，不表示所有 16 个位置都有独立人工确认 |
| 主机可能误用不匹配程序或不完整结果 | PS 检查硬件版本 0x00020002、数量和坐标有效性，异常独立报错 | 错误不会伪装成正常健康结果 |
| AXI 解码到检测器路径较长 | 输入流增加一拍寄存 | 隔离组合路径，算法仍在 PL 执行 |

保留 v2.1 的四次可分离 31×31 灰度闭运算加速方式，不回退到逐点扫描 31×31 窗口。两块 9 bit 帧 RAM 与有界洪泛队列复用，不新增完整图像 BRAM。

## 验证依据

- `tools/pl_detector_v22_model.py` 固定算法配置；`tools/precision_model.py` 提供整数参考。实验目录中的其他参数组合不属于发布算法。
- 8 组小尺寸 RTL 检查包含掩膜、框、重复输入、非法输入及队列溢出。
- 第 19、20 张完整尺寸 RTL 检查逐像素比较 31×31 闭运算/对比度，并比较掩膜、框与面积。
- 16 个独立连通域检查验证保留容量、坐标、排序和第 16 个红框开关。
- C 显示函数检查原图四边、灰度值、保留标志位及全部 65,536 个点的映射。
- 真实板卡 24 张全部完成，无检测器错误；每个框的数量、坐标、连通域面积与排序均与参考模型一致。`build/pl_detector_v22/board_results.json` 与 `build/pest_review/board_uart_v2_2.txt` 保留原始证据。

## 本次实测结果

| 项目 | v2.2 结果 |
|---|---|
| 第 14 / 16 / 17 / 19 / 20 张保留框数 | 4 / 6 / 6 / 2 / 1，原来为 1 / 3 / 1 / 1 / 3 |
| 第 20 张指定右侧背景位置 | 不再出框；第 17 张两个历史背景点也未被覆盖 |
| 第 19 张左边缘小斑 | 新增框；中央原有区域保留 |
| 原先第 24 张无框 | 现在上方小斑有 1 个框，图像判断与可见框一致 |
| 第 19 张 PL 处理 | 17,253,684 周期，100 MHz 下约 172.537 ms |
| 第 19 张 PS 预处理/上传 + PL | 220.015 ms |
| 第 19 张完整图片工作（显示准备 + 检测） | 355.460 ms，不包含等待 HDMI 下一帧的时间 |
| 24 张 PS 预处理/上传 + PL 最大时间 | 233.478 ms |
| 硬件时序 | WNS +0.141 ns、WHS +0.053 ns，无失败端点 |
| 资源 | 11,029 LUT、5,967 FF、60/60 BRAM36 等效块 |

BRAM 已满，后续增加整帧特征图或神经网络不能直接叠加，需要复用 RAM、调整存储结构或使用 DDR。此次没有增加独立完整帧缓存，但综合后的 BRAM 组织占用了全部 60 块。

24 张开发样本的图像级判断为 TP=12、TN=12、FP=0、FN=0。这仅说明这些图片上有无保留候选，不代表每个病斑都被找到或每个框都正确。用户指定第 17 张上方等位置仍有漏检，新增框数不是定位精度提升的充分证据。

发布构建和源码校验值见 `build/pl_detector_v22/manifest.json`。默认启动、构建和复测脚本已切换到实测后的 v2.2；保留 v2.1 bitstream 与 ELF，可用 `-Version 2_1` 回退。

## 不能混淆的指标

24 张是开发用图片，没有完整逐病斑真值框。某张显示 diseased 或新增框，均不能证明其所有病斑定位正确。不能用图像级分类统计替代定位精度、IoU 或病斑召回率。

第 16 张极暗叶尖及第 14 张部分细小、低对比度病斑仍是剩余问题。极暗叶尖与阴影的颜色、局部对比度接近，扩大暗色阈值曾造成健康样本阴影误报，因此未采用无约束放宽。后续需人工标注病斑与背景阴影，扩大独立测试集后再调整颜色/纹理或评估小型分割模型。现有 24 张结果只支持当前样本上的工程改进，不代表外部数据精度保证。

