# v2.4：控制修复与等价加速

日期：2026-10-25。基于 `32_v23_program_review.md` 落实优化。检测判定规则沿用 v2.3，不能将本次速度和稳定性改进解释为新的定位精度提升。

## 已落实的修改

| 审查问题 | v2.4 实现 |
|---|---|
| `s` 批测后图片与框错配 | 追踪显示图片和结果所属图片；批测结束重新检测当前样本；失败时保持隐藏；`o` 开启前检查对应关系 |
| 同一张图片按 `p` 重复生成显示图 | 复用当前图片的显示缓冲，换图才重新去噪、缩放、生成背景及上传 |
| 六遍二值 3×3 串行邻域扫描 | 每遍分为横向、纵向 3 点窗口，原地读写提前一像素读取，复制边界；复用原 RAM 和暂存位，不增加 PL BRAM |
| PS RGB 均值重复九点求和 | 三行水平和缓存，再做纵向求和并仅除以 9 一次，保持原整数舍入和边界语义 |
| 单缓冲切图可能显示新旧图混合 | PS 先准备显示图；上传前请求遮罩并等待一帧；像素域双触发同步且仅在帧边界启停遮罩；上传完再恢复 |
| 参数递增回绕 | 控制值限制为 10..264，对应实际 PL 门限 1..255；修改后立即重检，并打印实际 PL 门限 |
| 出错样本统计口径不一致 | 准确率按有效样本统计，另报检测器成功数；零有效样本不输出百分比 |
| 开机空循环可能被优化掉 | 改为有实际计时的等待，保留有限次数的寄存器写入与读回 |
| 历史入口会删除基础工程并下载不匹配程序 | 重建入口统一到隔离工程及严格时序检查流程；旧下载入口统一调用当前启动器；不再由普通入口删除基础工程 |

`tools/set_image.ps1` 的历史 ROM 换图入口已显式停止，防止把 ROM 图片更新误认为检测样本更新；固定 RGB 样本仍通过 `pv_samples.h` 准备。没有在本次加入网口传图、SD/Flash 独立启动。

## 等价性与资源

- 24 张实际板卡的框数量、坐标、连通域面积与顺序必须与 v2.3 完全一致；参考文件继续使用 `build/pl_detector_v23/python_results.json`，不重新调阈值。
- 第 14 张与健康第 10 张完整尺寸 RTL 仿真逐像素比较对比度和最终叶片/病斑掩膜，再比较框。
- 8 组小尺寸仿真检查重复帧、非法输入与队列溢出；另测 16 个独立框及第 16 框叠加。
- PS 行缓存均值用真实 C 函数核对 24 张完整 RGB 图片、常量、四角脉冲与随机输入。
- PS 控制代码由主机硬件替身直接调用，检查成功/失败批测恢复、叠加原先 OFF、缓存复用、门限端点。
- 图像遮罩仿真检查异步请求同步、仅在帧边界变化、遮罩期间无图像或红框像素泄漏。实机串口不能代替 HDMI 采集对画面的验证。

硬件版本标识为 `0x00020004`，编译宏为 `PL_RELEASE_22 PL_RELEASE_23 PL_RELEASE_24`。PS 检查硬件标识，避免错配旧 bitstream。资源为 11,161 LUT、6,027 FF、60/60 BRAM36 等效块；WNS +0.005 ns、WHS +0.021 ns，原时钟约束下通过时序，余量较小，不应据此提高时钟。

PS 增加约 256 KiB RGB 打包缓冲和约 4.5 KiB 行缓存，放在 DDR；单图显示缓存复用原有缓冲，没有缓存全部 24 张显示图。

## 已有实测与计时范围

本次第 14 张 PL 周期为 8,714,775（100 MHz，87.14775 ms）；v2.3 为 17,734,155（177.34155 ms）。减少 9,019,380 周期，框结果一致。

最终程序上板实测：

| 范围 | v2.3 已记录值 | v2.4 |
|---|---:|---:|
| 第 14 张 PL 检测 | 177.342 ms | 87.148 ms，约 2.03 倍 |
| 第 14 张 PS RGB 准备/上传 + PL | 224.102 ms | 120.032 ms |
| 第 14 张完整换图工作 | 359.313 ms | 254.128 ms，耗时减少约 29.3% |
| 第 14 张同图 `p` 重检 | 原流程仍重做显示准备 | 140.009 ms |
| 24 张 RGB 准备/上传 + PL 最大值 | 233.546 ms | 129.466 ms |

第 14 张新增阶段计时：RGB 行缓存均值 5.673 ms、AXI 上传 27.192 ms、PL 等待约 87.147 ms。后续若继续加速，AXI 上传是一个明确的剩余成本。

最终 24 张真实板卡结果与 v2.3 的每个框完全一致，检测器错误为 0。实机 `p → s → o → s → o → p` 验证两次批测后都恢复第 14 张的 7 个框，最后停在第 14 张、红框 ON。故障隐藏与参数上/下限由真实 C 控制代码的主机硬件替身检查补充覆盖。

完整换图时间包括 PS 显示准备、遮罩等待、图像上传、RGB 预处理与 PL 检测；同图重检复用显示结果，仍包含隐藏旧框到帧边界的等待。两者都不包含等待下一帧上所有像素实际显示完毕，也不是 HDMI 刷新率。

最终 PS/PL 程序及上板计时、校验值见 `build/pl_detector_v24/manifest.json`；全样本日志为 `build/pest_review/board_uart_v2_4.txt`，交互复测日志为 `build/pl_detector_v24/control_uart.txt`。

## 复现与回退

```powershell
# 重新构建并上板验证（不是日常启动所必需）
./tools/rebuild_pl_detector.ps1 -Version 2_4 -Sample 14
# 已有构建的全样本验证
./tools/verify_pest_board.ps1 -Version 2_4 -Sample 14
python tools/check_pl_board.py --version 2_4
# 停在第14张时检查 p/s/o 与批测后恢复
./tools/verify_control_v24.ps1
# 回退到之前已验证的版本
./tools/start_pl_demo.ps1 -Version 2_3 -Sample 14
```

启动仍可双击根目录 `启动病斑演示.cmd`。脚本结束会释放串口。

PS 主机检查可单独运行 `python tools/run_v24_checks.py`；v2.4 的完整重建已包含它及帧遮罩仿真。
