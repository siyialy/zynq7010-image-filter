## 为什么按键必须消抖

机械按键的触点在闭合瞬间会"弹跳"：几毫秒内通断几十次。50MHz 时钟每 20ns 采一次，能把这几十次弹跳**一次不漏**地采进来。如果直接拿它当控制信号，按一下会触发几十次（比如模式一下从"高斯"跳到"中值"）。

**消抖的本质**：不相信"瞬间的变化"，只相信"持续了一段时间的变化"。

## 模块里做了三件事（对应代码三段）

```
key_in ──▶ [两级同步器] ──▶ [计时消抖] ──▶ [边沿检测] ──▶ key_state
   (异步)      (打两拍)      (稳定1ms才认)    (产生单周期脉冲)   key_press
```

### 1. 两级同步器（`key_sync0` / `key_sync1`）

`key_in` 来自板子上的机械按键，和 `clk` 没有任何相位关系（异步）。直接用它驱动触发器，可能让触发器进入"既不是 0 也不是 1"的**亚稳态**，输出随机乱跳。

打两拍之后，信号就"驯服"到 `clk` 时钟域了。这是所有异步输入的第一道处理，**记住这个套路：外部信号进 FPGA，先打两拍**。

### 2. 计时消抖（`cnt` 计数器）

把同步后的信号和"已确认的稳定值 `key_state`"比较：

- 不一样 → 计数器 +1，数满 1,000,000 个时钟（20ms @50MHz）才把稳定值改掉
- 一样 → 说明刚才只是抖动，计数器清零

因为抖动每 5us 就翻一次，永远数不满 20ms，所以被自然过滤掉。

### 3. 边沿检测（`key_state_d` + `key_press`）

`key_state_d` 是 `key_state` 延迟一拍。当 `key_state` 从 1 变 0 时，这一拍里 `key_state_d=1`、`key_state=0`，两者一"与"就得到**只持续一个时钟周期**的脉冲。

为什么要脉冲？因为控制逻辑通常需要"事件"（按下了）而不是"状态"（一直按着）。一个脉冲正好触发一次动作，不会重复。

## 波形怎么看（图形界面里）

跑 `run all` 后打开波形，重点看三处：

| 信号 | 现象 |
|---|---|
| `key_in` | 在前 100us 内疯狂翻转（模拟抖动），之后稳定为 0 |
| `key_state` | 完全没有跟着抖，等到约 1ms 后才**台阶式**变成 0 |
| `key_press` | 只在 `key_state` 跳变的**那一拍**出现一根极窄的毛刺（单周期脉冲） |

如果 `key_state` 跟着 `key_in` 一起抖，说明消抖没生效；如果 `key_press` 连续出现多个脉冲，说明边沿检测写错了。

## 这里的 4 个可复用知识点（后面项目全靠它们）

| 知识点 | 在本项目哪里用 |
|---|---|
| 两级同步器 | 摄像头 PCLK 域的 VSYNC/HSYNC 进主时钟域 |
| 计时消抖 | PL KEY 切换滤波模式 |
| 单周期脉冲 | 模式切换只触发一次、帧起始标志 |
| 参数化 | `DEBOUNCE_MS` 改一下就能复用到别处 |

## 自己动手改（检验你真的看懂了）

1. **把 `DEBOUNCE_MS` 改成 5**，重跑仿真。预测一下：抖动 100us 会不会被误认成有效按下？答案是不会（100us << 5ms），结果仍应 PASS。
2. **把 `ACTIVE_LOW` 改成 0**，重跑。这时候按下=高电平，`key_press` 应该变成上升沿触发——但 testbench 里还是按低有效写的，所以会 FAIL。想一想怎么改 tb。
3. **挑战题**：加一个 `key_long_press` 输出，按住超过 1 秒时输出高电平。提示：再开一个计数器，从 `key_state==0` 开始数。
