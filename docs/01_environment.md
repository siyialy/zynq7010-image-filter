## 2. 启动 Vivado 的三种方式

1. **开始菜单**：搜索 `Vivado 2018.3` → 点开（最省事）。
2. **直接运行**：`D:\XILINX\Vivado\2018.3\bin\vivado.bat`（双击即可）。
3. **命令行批处理**（我给你的脚本就是这样跑的）：
   ```
   D:\XILINX\Vivado\2018.3\bin\vivado.bat -mode batch -source 脚本路径.tcl
   ```

> 第一次启动可能要 1~3 分钟（要初始化 Tcl 解释器和器件库），之后会快一些。启动过程 CPU 占用高是正常的。

**SDK 启动**：`D:\XILINX\SDK\2018.3\bin\xsdk.bat`。SDK 只在你要写 ARM 程序时用（阶段 S2 开始）。

## 3. 关于版本：为什么用 2018.3 而不是 2025.2

竞赛指南原文（`_ref/AMD赛道.txt` 第 879~881 行）：

> 工具版本：Vivado / Vitis 2026.1（推荐）或 2025.2。**如使用其他版本需在报告中说并保证脚本可复现**。

所以 2018.3 是**允许的**，只要做到两点：
1. 在报告里写清楚版本与理由（Zynq-7010 为成熟器件、本机已有授权、避免数百 GB 下载与长时安装）。
2. **所有工程都用 Tcl 脚本从源码重建**，不依赖 .xpr 文件——这样别人用 2025.2 也能重建（我们后面的脚本会做到这一点）。

不建议现在去下 2025.2：安装包约 100 GB、装完还要 2~3 小时，而且新版把 SDK 换成 Vitis，流程差异会让零基础的人多踩一堆坑。

## 4. 关键规则：Vivado 工程路径必须是纯英文

Vivado 2018.3 对**中文路径**支持很差，症状是：综合时报奇怪的错、IP 生成失败、仿真器找不到文件。

所以约定：

- **源码、文档、脚本**放在 `D:\FPGA比赛\`（中文目录，没关系，这些是纯文本操作）。
- **Vivado 工程目录必须放在纯英文路径**，例如：
  ```
  D:\fpga_build\
  ```
  我给你的 Tcl 脚本默认会把工程建到 `D:\FPGA比赛\build\...`，如果 simulation 因为中文路径报错，就把输出目录改到 `D:\fpga_build\...`（脚本支持传参）。

## 5. 顺便把这几个概念存进脑子

| 名字 | 是什么 | 你要用它做什么 |
|---|---|---|
| Vivado | 硬件开发工具（写 Verilog → 仿真 → 综合 → 生成 .bit） | 90% 的时间在这里 |
| SDK | ARM 端 C 语言开发环境 | 写 PS 程序（配置、菜单、统计） |
| .bit 文件 | FPGA 的"配置数据" | 上板加载，PL 才会工作 |
| .hdf / .xsa | 硬件描述文件，从 Vivado 导出给 SDK | SDK 靠它知道有哪些外设和地址 |
| 综合（Synthesis） | Verilog → 门电路网表 | 检查你写的能不能变成电路 |
| 实现（Implementation） | 网表 → 布局布线 | 检查时序能不能收敛（WNS ≥ 0） |
| 时序（Timing） | 信号能不能在时钟周期内走完 | 视频 148.5MHz 时最容易出问题，后面细讲 |
