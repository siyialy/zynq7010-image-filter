日期：2026-10-25。以人工审核完成的 24 张开发图片、85 个病斑框为基准。**这是离线候选算法，尚未移植到 Verilog、编译 bitstream 或上板验证。板卡和默认启动程序仍为 v2.4。**

## 采用的规则

1. **保留基础分支的可靠小/中候选。** 基础分支仍先采用 v2.4 的 16 框筛选；超大区域转交精化分支，不直接画覆盖大片叶片的大框。对面积较大且平均对比度不足的候选增加抑制条件。
2. **在大候选上下文中精化。** 从基础掩膜中记录大连通域，扩大有限范围作为后续搜索上下文。精化候选必须大部分位于这些范围内，避免在整张图片中无约束补框。
3. **较严格的颜色核心与不同腐蚀尺度。** 用经典颜色核心减弱黄色正常组织、叶脉造成的连桥；对不同大小的核心做 5×5、7×7 腐蚀，分离相连区域，再恢复有限边界。一个分支补充连续褐色叶片区域，以减少部分坏死组织被叶片掩膜切掉的问题。
4. **分支去重和碎片合并。** 优先保留较明确的精化核心，合并相近或交叠的补充分片，抑制与基础分支重复的框。
5. **组合输出容量 32。** 基础分支仍保留原 16 框，精化分支补充后统一限制为 32；不是简单把原全部候选放宽到 32 个。
6. **显示边界改为紧凑整数映射。** 去掉原先统一的两显示像素外扩，使用 320×240 显示网格上的整数边界。投影评估使用可实现的整数坐标，不使用理想浮点框来抬高小目标 IoU。

显示投影召回提升既包括新找到的病斑，也包括显示边距和量化修正；不能把 33→61 全部解释为新增病斑。真实新增源图病斑为 7 个。

## 未采用的尝试

- 只把原候选容量扩到 32：TP 仍为 55，FP 增到 23，说明漏检主要不是单纯被名额挤掉。
- 整体放宽叶片颜色范围：丢失原来正确框，部分方案还使健康样本出框。
- 直接用小窗口替代原局部对比度：产生大量碎框，单独使用会损失大病斑匹配。
- 全面收紧颜色候选或统一腐蚀全部掩膜：会抹掉原先正确的小病斑。

实验日志和候选比较保存在 `build/algorithm_v25/`；未采用方案不属于发布算法。

## 可复现入口

```powershell
python tools/evaluate_v25.py
python tools/test_v25_reference.py
python tools/preview_v25.py
```

- `tools/lesion_detector_v25.py`：独立检测函数，只接收一张 PS 等效平滑 RGB，不接收样本编号或标注。
- `tools/precision_v25_core.py`：冻结的整数运算参考。
- `build/algorithm_v25/candidate_verified.json`：逐图结果、框、真值 SHA256 与代码 SHA256。
- `build/algorithm_v25/before_after.jpg`：整体对照；各张图片另有独立 PNG。

预览由未改变的 C 显示函数重建像素，再叠加旧框或离线新框，**不是新版 HDMI 采集图**。

合成测试检查常量输入、平移、重复图片与调用顺序独立性、显示边界、输入尺寸及数据不被修改。这些测试不读取人工标注。标注驱动评估另行检查全部 24 张，无回退原已匹配病斑、无健康开发样本新增框，标注文件校验值不变。

## PL 移植需要处理的事项

| 项目 | 需要的硬件工作 |
|---|---|
| 32 框 | 同步修改坐标数组、数量位宽、跨时钟域总线、画框器和 PS 读回；原坐标选择器范围会与面积读回范围重叠，必须重新分配协议 |
| 多分支 | 复用共同灰度闭运算与帧 RAM，按上下文处理精化；不能把 Python 的四次完整检测直接复制成四套硬件 |
| 褐色叶片补充标志 | 当前元数据位已满，需要重新编码、复算或规划额外小容量分布式存储 |
| 父区域、分支优先级、碎片合并 | 增加有上限的候选列表和顺序比较状态，并检查溢出处理 |
| 紧凑显示框 | 同步源图到显示坐标映射，并逐框核对真实 HDMI 边界 |
| 资源/速度 | v2.4 已占 60/60 BRAM，且时序余量小；新版本必须重新验证资源、时序和实际延时，不能承诺仍是 87 ms |

因此本轮没有把离线结果伪装成已上板程序，也没有用 PS 直接返回预先保存的图片框。默认工程仍运行 v2.4。

## 局限

本轮用现有 24 张人工标注选择规则，所有数字都是开发集结果，不是独立测试精度。55 个原匹配框仍有候选接受带来的边界锚定；新的阈值、尺寸及颜色条件仍可能对其他叶片失效。应保留这版开发基线，再增加独立图片验证，而不是追求在这 85 个框上全部匹配。
