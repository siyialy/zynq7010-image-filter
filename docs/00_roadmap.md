# 总路线图：从零基础到能演示的作品

## 0. 先把"要做什么"想清楚

你不是要"学完 FPGA"，你是要**做出一个能在评委面前跑起来的系统**。所以路线设计的核心原则：

- 每一步都有**能在屏幕上看到的产出**（波形、LED、串口打印、显示器出图），绝不连续两周看不到结果。
- 先**纵向打通最短链路**（彩条 → 滤波 → HDMI），再补摄像头、补模式、补指标。
- 摄像头是最后才接的"外设"，因为它最容易出问题（I2C、时钟、分辨率、时序全都不确定）；先让 PL 自己生成测试图案，链路稳了再换源。

## 1. 五个阶段

### 阶段 S1：数字逻辑与 Verilog 基础（预计 10~14 天）

| 步骤 | 内容 | 验收标准（做到了才算过） |
|---|---|---|
| S1-1 | 仿真点灯 | 跑通 `build/sim_led_blink.tcl`，终端打印 `PASS`，波形里看到 led 周期翻转 |
| S1-2 | 上板点灯 | 板子上的 LED 真的在闪（需要 XDC 引脚约束） |
| S1-3 | 按键消抖 + 状态机 | 按一下键 LED 状态切换一次，不抖、不连跳 |
| S1-4 | 自己写 testbench | 能给自己写的模块造激励、会看波形、会用 `$display` 打印检查 |

要建立的心智模型（只需这 5 条）：
1. Verilog 不是"程序"，是**描述电路**。`always @(posedge clk)` 里面写的就是"一排触发器"。
2. 一切都在**时钟节拍**上发生；`<=` 是非阻塞赋值，代表寄存器输出。
3. 组合逻辑用 `assign` / `always @(*)`，里面用 `=`。
4. 一个模块 = 一个带输入输出端口的黑盒；模块之间用线（wire）连。
5. 仿真 = 给黑盒喂波形；综合 = 把黑盒变成真正的门电路。

### 阶段 S2：ZYNQ 软硬件协同入门（预计 10~14 天）

| 步骤 | 内容 | 验收标准 |
|---|---|---|
| S2-1 | PS 最小系统 | Zynq PS IP + 串口，SDK 里打印 "Hello ZYNQ" |
| S2-2 | AXI GPIO | PS 用 C 代码控制 PL 的 LED，按键状态能读回串口 |
| S2-3 | 自定义 AXI-Lite IP | 自己写一个寄存器模块挂到 AXI 总线上，PS 能读写（这是滤波参数寄存器的原型） |
| S2-4 | 中断 / 定时器 | PS 定时器中断里翻转 LED，串口打印计数 |

这一阶段的意义：**"软硬件协同"不是口号，就是 PS 通过 AXI 总线读写 PL 的寄存器**。滤波 IP 的模式、阈值、系数，都是这么传进去的。

### 阶段 S3：视频通路（预计 15~20 天，项目核心）

| 步骤 | 内容 | 验收标准 |
|---|---|---|
| S3-1 | 视频时序原理 | 自己写一个 640×480@60 的时序发生器（HS/VS/DE/pixel_clk），显示器出彩条 |
| S3-2 | AXI4-Stream 握手 | 理解 `tvalid/tready/tlast/tuser`，把视频流改造为标准 Stream |
| S3-3 | **3×3 卷积滤波 IP**（核心创新点） | 行缓存（line buffer）+ 3×3 窗口 + 乘加，仿真验证 Sobel 输出正确 |
| S3-4 | 上板联调 | 彩条 → 滤波 → HDMI，显示器上实时看到边缘检测/模糊效果 |

### 阶段 S4：多源图案 + 全链路上板（预计 12~15 天）

> **决策（2026-10-20）：不用 OV5640 摄像头。** 视频源改用"片内图案发生器 + 图片 ROM"。
> 理由：摄像头的 I2C 初始化、DVP 时序、引脚定义是最容易卡死的一环，且不贡献"硬件加速"这个卖点。
> 接口在设计上预留，作为可选扩展（S6）。

| 步骤 | 内容 | 验收标准 |
|---|---|---|
| S4-1 | 彩条 → 滤波 → HDMI 全链路 | 显示器上实时看到"彩条被 Sobel 变成 7 条竖亮线" |
| S4-2 | 动态图案发生器 | 移动方块 / 扫描渐变 / 棋盘，60Hz 逐帧变化，滤波结果同步变化 |
| S4-3 | 图片 ROM | 一张实拍图（`.coe` 写进 BRAM）作为图像源，原图/模糊/边缘对比清晰 |
| S4-4 | 多模式实时切换 | PL KEY 或串口切换 4 种模式，切换瞬间生效、不撕裂不卡顿 |
| S4-5 | 提分辨率/帧率 | 640×480@60 → 1280×720@60（视时序裕量决定，720p 注意同步极性为正） |

### 阶段 S6（可选加分）：摄像头扩展 / VDMA 软件基线

| 步骤 | 内容 | 价值 |
|---|---|---|
| S6-1 | OV5640 DVP 采集接入 | 证明接口能力，演示"真摄像头实时" |
| S6-2 | PS + DDR + VDMA 帧缓冲 | PS 能拿到同一帧，做**同一帧的软件滤波对比**，加速比数据最硬 |

### 阶段 S5：作品化（预计 10~14 天）

| 步骤 | 内容 | 产出 |
|---|---|---|
| S5-1 | 指标采集 | 帧率、单帧延迟、PL 资源（LUT/FF/BRAM/DSP）、时序 WNS → `metrics/metrics.csv` |
| S5-2 | 软件基线 | 同一帧数据用 ARM 纯软件滤波，测耗时 → 算加速比（这是"为什么要硬件加速"的证据） |
| S5-3 | 交互界面 | 串口菜单或上位机，展示模式切换与实时效果 |
| S5-4 | 文档与交付 | 设计报告、README 复现步骤、演示视频、开源仓库、skill 包 |
