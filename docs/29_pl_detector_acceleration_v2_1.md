## 为什么变快

v2.0逐像素读取31×31邻域，分别做二维灰度膨胀和腐蚀，单这两步每帧要读取约1.26亿个邻域样本，是主要耗时来源。

正方形结构元素可精确分解，v2.1改为：

```text
横向最大值 → 纵向最大值 → 横向最小值 → 纵向最小值
```

每条扫描线读取一次输入，窗口历史由30项小型移位寄存器保存。比较树并行归约窗口极值，输入和中间结果分级寄存，满足100MHz时序。

每个原地扫描通道先读到待输出位置之后R个像素，再写入结果；被覆盖的旧像素保留在窗口历史中。边缘采用复制填充，首尾均补齐R个样本。中间亮度和掩膜仍复用原来的两块9位帧RAM，不新增整帧BRAM。

阈值、亮度量化、叶片分割、病斑形态学、连通域、周围组织支持、排名、去重及最多8框限制均未改动。本轮也没有把检测移回PS。

## 正确性与硬件检查

- 原8组合成输入全部通过：逐像素叶片/病斑掩膜、框数、坐标、面积、重复换帧、缺失帧与前沿队列溢出。
- 实际256×256、R=15验证包含真实第15张和平滑变化的灰度地形。每个像素的31×31闭运算对比度、掩膜、最终框和面积均与Python/PIL二维参考一致。
- JTAG下载新bitstream及ELF，板卡运行全部24张。所有框数、坐标、核心面积和顺序与Python以及保存的v2.0硬件读回完全一致，错误计数0。
- 分类仍为TP11、TN12、FP0、FN1，即23/24；第24张仍未检出可靠病斑。本次是等价加速，没有解决原有漏检，也不把开发样本成绩当作独立测试集准确率。
- 最终LUT 6884/17600，FF 4294/35200；BRAM仍为59.5/60，没有增加整帧缓存。
- 最终WNS +0.006ns、WHS +0.030ns，setup/hold无失败端点。setup余量较小，后续改动必须重新实现并复核，不能仅凭仿真下载。

最初未加流水级的比较树存在时序违例，未上板；增加输入和中间寄存器后，再做布局布线物理优化完成时序收敛，没有放宽时钟约束或添加多周期例外。

## 文件及使用

- 硬件：`D:/fpga_build/bits/system_top_v2_1.bit`。
- 固件：`build/pest_review/img_filter_app_v2_1.elf`，编译宏`PEST_USE_PL`和`PEST_FAST_PL`，含硬件版本校验。
- 已通过时序的工程：`D:/fpga_build/pl_detector_1792835453`，最终检查点`detector_timing_closed.dcp`。
- 实测串口：`build/pest_review/board_uart_v2_1.txt`。
- Python/板卡对照：`build/pl_detector_v21/board_results.json`。
- 构建、源码和二进制哈希：`build/pl_detector_v21/manifest.json`。

双击根目录`启动病斑演示.cmd`，默认加载v2.1；启动器仍使用本次进程的PowerShell执行策略，不修改长期系统设置。JTAG下载时间不属于单张识别耗时。

```powershell
./tools/start_pl_demo.ps1                 # 默认v2.1，第15张
./tools/start_pl_demo.ps1 -Version 2_0   # 加载保留的旧版程序
./tools/rebuild_pl_detector.ps1 -Version 2_1 -Sample 15
python tools/check_pl_board.py --version 2_1
```

构建入口会检查时序；若仅有小幅违例，会调用`build/finish_pl_detector_timing.tcl`进行物理优化。只有setup/hold均通过才发布bitstream。旧v2.0 bitstream及ELF均保留，便于回退。当前板卡停在15，COM7已释放。
