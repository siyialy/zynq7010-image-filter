## 数据流

1. PS 读取内置 256×256 RGB，对检测输入做一次精确 3×3 均值，保留打包结果。
2. PS 选择模式 0，上传 RGB，由一个 PL 引擎完成基础检测；PL 保存可靠基础框和大连通域上下文。
3. 没有大区域上下文时，PL 直接发布结果。否则 PS 依次选择模式 1、2、3，重复上传同一份预处理 RGB。
4. PL 复用同一套帧 RAM、局部灰度闭运算、形态学和连通域引擎，执行三个精化配置。四轮顺序执行，不是四套并行引擎。
5. PL 完成上下文约束、去重、碎片合并、优先级排序，最多保留 32 框，再统一发布。中间轮次不发布病斑框。
6. 像素时钟域在帧边界锁存结果，HDMI 实时叠加红框。PS 从同一份结果读回分类、框和面积。

每轮重新计算灰度闭运算，以适配 60/60 BRAM 的存储约束。精化会增加处理时间；需要用真实板卡日志报告延时，不能沿用 v2.4 的 87 ms。

## 硬件实现

- `pl_pest_engine_v25.v`：可配置基础/严格颜色核心/褐色叶片/额外腐蚀，32 个候选使用单写口分布式 RAM，顺序搬移排序和删除，避免大量并行寄存器移位。
- `pl_candidate_fusion.v`：32 个父区域、32 个最终框、96 个分支候选，上限溢出显式报错；合并顺序、整数重叠比例和稳定排序对应离线参考。
- `pl_detector_v25.v`：管理轮次、状态、最终提交和显示保持。复用一套检测引擎。
- 32 框数量占 6 位；总线 1536 位，前 8 位控制，其后每框 44 位 HDMI 坐标。旧版本仍由宏隔离。
- 存储不复位，使用有效计数保护读取；新逻辑图像开始清空计数及错误，轮间只清引擎。
- 邻域标记使用对应 RAM 读操作已锁存的地址，写地址不依赖该拍读出的掩膜位；避免存储器读出到写地址的反馈长路径，不增加检测状态或周期。

验证包括：全部 24 图的融合/紧凑显示/HDMI 总线对比；第 21、23、10 张四轮检测的每个灰度对比度与掩膜像素及候选框顺序；独立 40 候选取 32、满表后高分插入排序、32 个最终框及最后一个框实际命中、父区域溢出与重置。最终下载仍以资源、setup/hold 和板卡 24 图核对通过为前提。

## 寄存器协议

沿用 0x43C00000 基地址和原上传接口，命令地址 80004，每字为 `{opcode,reserved,selector,brown_cut}`。

| 命令 | 含义 |
|---|---|
| 1 | 开始当前轮 RGB 上传；模式 0 同时开始新的逻辑图像 |
| 2 | 运行当前轮，等待检测与该轮融合结束后才置 done |
| 3 | 中止引擎/当前融合操作，轮间已保留的候选仍在 |
| 4 | 选择读回项 |
| 5 / 6 | 保持/恢复画面，沿用 v2.4 |
| 7 | selector 的低 2 位指定模式 0..3 |

| 读 selector | 返回值 |
|---|---|
| 0 | D2 特征头、数量 [13:8]、active/error/done/busy |
| 1 | 当前轮检测与融合周期，PS 累加各轮 |
| 2 | 本轮完整 RGB 像素接收数，应为 65536 |
| 3 | 0x00020005，PS 与 PL 不匹配则拒绝运行 |
| 4 | bit 0：本轮结束；bit 1：最终结果已发布，可停止上传后续轮次 |
| 16..79 | 32 个显示框，每框两项，xy 低/高端点，含末像素 |
| 80..143 | 源图框端点，半开区间，最大右/下端点为 256 |
| 144..175 | 原连通域面积；合并框保留首片面积，与参考一致 |

读回索引与状态经过寄存器分级以满足 100 MHz 时序。v2.5 PS 驱动选择读项后先完成一次丢弃的 AXI 状态读，再取下一次读值，保证索引、坐标和读回数据已经稳定。

## 复现

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/rebuild_v25.ps1 -SkipProgram
# 资源/时序、RTL 检查通过之后才执行下载：
powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify_pest_board.ps1 -Version 2_5 -Sample 14
python tools/check_pl_board.py --version 2_5
```

`build/pl_detector_v25/` 保存逐像素参考向量、仿真、板卡结果及硬件构建路径。`build/algorithm_v25/candidate_verified.json` 仍是离线开发集评估，硬件验证状态与耗时另记本目录的发布记录。原 v2.4 bit/ELF 保留用于恢复。

日常重新上电后，连接 JTAG、USB 串口和 HDMI，关闭串口终端，然后双击根目录的 `启动病斑演示.cmd`，默认加载校验通过的 v2.5 并显示第 14 张。启动器会核对 bit/ELF 的发布哈希；重新编译后的文件未验证时不会作为已验证版本启动。下载仍为 JTAG 临时加载，本轮没有制作 SD/Flash 启动镜像。

需要恢复旧版时可显式执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start_pl_demo.ps1 -Version 2_4 -Sample 14
```

本版规则仍来自已有 24 张开发图片，精度数字不能视为独立测试集表现。剩余漏检及误框不会因硬件等价移植自动消失。
