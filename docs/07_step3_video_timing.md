## 显示器只认三样东西

```
         |<---- 可见区 640 ---->|<- 前肩16 ->|<- 同步96 ->|<- 后肩48 ->|
  一行：  像素 0 ... 像素 639      黑         黑           黑
  DE  ：  1  1  1 ... 1  1        0          0            0
  HSYNC:  1  1  1 ... 1  1       1         0（低有效）     1
```

- **像素时钟**：每来一个上升沿，总线上的颜色就被"抓"走一个像素
- **HSYNC**：告诉显示器"这一行结束了，回去准备下一行"
- **VSYNC**：告诉显示器"这一帧结束了，回左上角"
- **DE（数据有效）**：只有 DE=1 的那 640 个像素会显示，其余是消隐期

**为什么要有消隐期**：老式 CRT 的电子束要时间"飞回"行首/帧首，这段时间不能有图像；现代 LCD 沿用了这套规范，所以必须遵守，否则显示器不认。

## 关键算术（记下来，答辩会被问）

```
行总长 = 640 可见 + 16 前肩 + 96 同步 + 48 后肩 = 800 像素
帧总行 = 480 可见 + 10 前肩 +  2 同步 + 33 后肩 = 525 行
帧率   = 像素时钟 / (800 × 525) = 25.175MHz / 420000 ≈ 59.94 Hz
```

**注意**：25.175MHz 不是整数倍关系，所以真实板子上必须用 MMCM/PLL 生成，不能用分频凑（凑不准会让显示器黑屏或抖动）。

## 想换成 720p 只改参数

| 参数 | 640×480@60 | 1280×720@60 |
|---|---|---|
| 像素时钟 | 25.175 MHz | 74.25 MHz |
| H_VISIBLE / FP / SYNC / BP | 640 / 16 / 96 / 48 | 1280 / 110 / 40 / 220 |
| V_VISIBLE / FP / SYNC / BP | 480 / 10 / 2 / 33 | 720 / 5 / 5 / 20 |
| 行总长 × 帧总行 | 800 × 525 | 1650 × 750 |
| 同步极性 | 低有效（H/V_SYNC_POL=0） | **高有效**（=1） |

**720p 的同步极性是正的**，这是新手最容易搞错的地方（改分辨率后黑屏，八成是这个）。

## 波形窗口里看什么

| 信号 | 现象 |
|---|---|
| `hsync` | 每 800 个像素出现一次低脉冲，宽度正好 96 拍 |
| `vsync` | 每 525 行出现一次低脉冲，宽度 2 行 |
| `de` | 高电平持续 640 拍，然后低 160 拍，规律循环 |
| `x` / `y` | x 从 0 数到 799 归零；y 每行加 1，数到 524 归零 |
| `rgb` | 每 80 个像素换一种颜色，8 段正好铺满 640 |

## 为什么先做彩条，不先接摄像头

彩条有**已知正确的颜色和位置**，能把"显示器出图"这一环的不确定性单独隔离出来。真出问题时你只需要查三件事：时钟频率对不对、极性对不对、DE 位置对不对。如果一开始就接摄像头，黑屏时你分不清是摄像头、I2C、时序还是 HDMI。

而且竖彩条有 7 条**垂直硬边**，正好用来检验下一步的 Sobel 边缘检测——滤波后应该只看到 7 条竖亮线，其余全黑。
