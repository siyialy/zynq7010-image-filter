# 第 7 步：HDMI 输出上屏（720p60，彩条 + 实时滤波）

> 这一步把"验证过的滤波流水线"接到真实 HDMI 接口上。烧进去之后，显示器上就能看到
> **8 条彩条**，按 KEY0 切换模式，实时看到 **Sobel 7 条竖亮线 / 高斯模糊 / 灰度**。

## 成果

| 项目 | 结果 |
|---|---|
| 分辨率 | **1280×720@60**（行 1650 / 场 750，像素时钟 75MHz） |
| 时序 | **WNS = +4.063 ns**（时序收敛，裕量充足） |
| 资源 | LUT 678 / 17600（3.85%），FF 478（1.36%），BRAM 0.5 块，DSP 1 个，IOB 13 |
| 综合/实现 | 0 Errors / 0 Critical Warnings |
| bit 流 | `board/bitstream/hdmi_top.bit`（约 2 MB） |

## 架构

```
sys_clk 50MHz ──▶ clk_wiz_0 (MMCM, VCO=1125MHz)
                    ├──▶ pixel_clk     75MHz   ──┐
                    └──▶ pixel_clk_5x  375MHz    │
                                                 ▼
                 video_pipeline（1280×720@60）
                   彩条图案 → 3×3 滤波 → 输出寄存
                            │ rgb / hs / vs / de
                            ▼
                 dvi_transmitter_top
                   ├─ dvi_encoder × 4（8b/10b TMDS 编码，蓝通道带同步）
                   ├─ serializer_10_to_1 × 4（OSERDESE2 10:1 DDR 串行化）
                   └─ OBUFDS × 4（TMDS_33 差分输出）
                            │
                            ▼
                      HDMI 接口 → 显示器
```

TMDS 编码器和 OSERDES 串行化用的是**正点原子官方 `22_hdmi_colorbar` 例程的实现**（已核对并集成），
时钟参数（75MHz + 375MHz）也对齐官方例程，只是把"彩条图案"换成了我们自己的
`video_pipeline`（彩条 + 3×3 滤波 + 模式切换）。

## 怎么用（烧进去之后）

| 操作 | 现象 |
|---|---|
| 上电/Program 之后 | 显示器出现 **8 条竖彩条**（白黄青绿品红红蓝黑） |
| 按一次 **KEY0** | 切到 **灰度**（彩条变灰度渐变，LED 显示 `01`） |
| 再按一次 | 切到 **均值模糊**（彩条边缘变软，LED `10`） |
| 再按一次 | 切到 **高斯模糊**（更自然的模糊，LED `11`） |
| 再按一次 | 切到 **Sobel 边缘**（全黑背景 + 7 条竖亮线，LED `00`） |

LED[1:0] 用二进制显示当前模式，按住 KEY1 可以看 LED 变化（KEY1 目前预留给后面的"模式锁定/对比原图"）。

## 时序问题与修复（这一段很值得写进报告）

第一版综合实现后 **WNS = -0.140 ns**，5 个端点不收敛。关键路径：

```
u_flt/y_s2_reg[9] → ... → out_rgb_reg[21]     13 级逻辑（CARRY4×4 + DSP48E1×1）
Data Path Delay 13.411ns  要求 13.333ns（75MHz）
```

原因：滤波核把「九抽头 → 加法树（9 个加数）→ 乘法 → 移位 → 模式选择 → 输出寄存」
全挤在一拍里，组合逻辑太深。

**修复**：把算术流水线加深为 3 级

| 级 | 做什么 | 组合深度 |
|---|---|---|
| S4 | 寄存九抽头 | 打断"移位寄存器 → 加法树" |
| S5 | 加法树求和并寄存 | 纯加法，约 3~4ns |
| S6 | 乘法/移位/绝对值，寄存每种模式的结果 | 约 3~4ns |
| S7 | 模式 mux + 输出寄存 | 1 级 LUT + 寄存器 |

结果：**WNS 从 -0.140ns 提升到 +4.063ns**，代价是总延迟从 5 拍变成 8 拍（对显示毫无影响）。

**顺带修的两个坑**（都是加深流水线时暴露的）：

1. **DRC REQP-1840**：行缓存读地址 `addr_s1` 原来带异步复位，却被直接连到 BRAM 地址端口，
   异步复位可能损坏存储器内容。→ 改成不带复位（地址寄存器本来就不需要复位）。
2. **mode 0 错位 1 像素**：加深流水线后，`r_gray <= w11` 用的 `w11` 到 S6 时已经又往前走了两列，
   导致灰度模式整体偏移。→ 在 S5 同拍把窗口中心寄存成 `gray_c`，S6 用 `gray_c`。

**第 2 个坑的教训**：流水线一加深，所有"直接引用前级寄存器"的地方都要重新检查对齐。
验证手段就是那个"坐标比对"的 testbench——它立刻报出 `mode 0` 有 329 个像素错位，而其他模式全对，
一眼就能定位到"只有中心抽头被引用了两次"。

## 上板步骤

1. 板子上电，`BOOT CFG` 两个开关拨 **ON**（JTAG 模式）
2. HDMI 线接显示器和板子 `HDMI OUT`
3. 下载器接 `JTAG`，Vivado → `Open Hardware Manager` → `Auto Connect`
4. 右键 `xc7z010_1` → `Program Device` → 选 `board/bitstream/hdmi_top.bit` → Program
5. 显示器应在 2~3 秒内出彩条

## 排障表

| 现象 | 可能原因 | 怎么查 |
|---|---|---|
| 显示器"无信号" | 分辨率/帧率不被接受 | 换一台显示器或电视试；确认是 720p60 |
| 一直黑屏但显示器有信号 | `clk_locked` 没起来 | 检查 `reset` 极性（官方例程是 `~sys_rst_n`）、复位键是否卡住 |
| 花屏/雪花 | TMDS 差分对引脚接错（P/N 反） | 核对 J20/H20、K19/J19、G19/G20、J18/H18 |
| 图像偏色 | RGB 通道顺序错 | `video_din[23:16]=R`、`[15:8]=G`、`[7:0]=B` |
| 图像撕裂/抖动 | 时序未收敛 | 看 `report_timing`，WNS 必须 ≥ 0 |
| 闪烁但能显示 | 帧率偏低（75MHz/1650/750 = 60.6Hz） | 正常现象，多数显示器能接受 |
