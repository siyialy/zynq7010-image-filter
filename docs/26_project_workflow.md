# FPGA 叶片病斑检测与显示项目流程（历史 v1.7）

当前运行版为 v2.4：PS 预处理、PL 检测、16 个框及 HDMI 输出。当前完整流程、定位修改和实测见 [v2.4 优化说明](33_workflow_optimization_v2_4.md) 及 [完整流程](30_precision_workflow_v2_2.md)；下文为历史 v1.7，PS 检测等描述不适用于当前程序。

## 一、项目目标与分工

项目使用 Zynq-7010，实现叶片样本检测、病斑框定位、图像滤波和 HDMI 显示。

- PS：ARM Cortex-A9 运行裸机 C 程序，负责样本读取、病斑检测、显示图像预处理、串口交互及控制寄存器。
- PL：FPGA 逻辑负责图像缓存读取、视频时序、可切换 3×3 滤波、红框叠加及 HDMI 输出。
- PS 与 PL 通过 AXI4-Lite 传送图像、框坐标和控制信息。

当前病斑检测是 PS 上的颜色、形态学和局部对比度规则算法，没有部署神经网络。当前演示输入是程序内置样本，不是摄像头实时采集。

## 二、运行流程

```text
24 张内置 RGB 样本（每张 256×256）
                  ↓
        PS 读取当前图片的原始 RGB
                  ↓
     检测：平滑 → 叶片分割 → 局部病斑候选
                  ↓
    形态学处理 → 组织支持与形状检查 → 边缘扩展
                  ↓
       候选去重、排序，保留最多 8 个框
                  ↓
        有保留框：DISEASED
        无保留框：NO_RELIABLE_LESION
                  ↓
     用原图生成显示画面（与检测预处理分别处理）
     灰度 → 中值滤波 → 双边滤波 → 双线性缩放
                  ↓
      320×240 主画面 + 32×60 柔和背景数据
                  ↓
       AXI4-Lite 上传图像、框坐标和控制配置
                  ↓
     PL 图像缓存 → 视频源 → 可切换 3×3 滤波
                  ↓
        滤波后叠加红框 → HDMI 显示器
```

### 1. 图片输入

`ps_app/pv_samples.h` 保存 24 张 256×256 RGB 图片。前 12 张为健康标签，后 12 张为早疫病标签；标签用于评价，不参与检测决策。串口命令 `n`、`b` 切换图片，`p` 重新检测当前图片。

### 2. PS 病斑检测

主要实现在 `ps_app/pest.c` 的 `pest_detect()`。

1. 对原始 RGB 做 3×3 平滑，抑制孤立颜色噪声。
2. 用绿色、黄色及饱和棕色组织生成叶片种子；闭运算、最大连通域、孔洞填充及边缘收缩生成保守叶片掩膜。
3. 在同一叶片掩膜内统计棕色像素，避免背景污染比例。
4. 以 31×31 灰度闭运算估计局部亮度背景，提取具有局部明暗差的棕色或灰褐色候选。
5. 开、闭运算处理细桥和裂隙，连通域分析得到候选区域。
6. 检查面积、长宽比、填充率、周围叶片组织支持等条件。v1.7 补充灰褐色且被组织包围的病斑分支，恢复 15、19 的主要病斑。
7. 仅从通过验证的核心出发，在满足颜色、对比度和叶片范围的像素中最多扩展 3 步，改善褪色边缘覆盖。
8. 转换坐标，按核心对比度总和排序、去重，保留最多 8 个框。
9. 最终判定与保留框保持一致。没有框表示未检出可靠病斑，不能证明叶片健康。

### 3. PS 显示预处理

`pest_render()` 使用原图生成显示数据：RGB 转灰度、3×3 中值滤波、5×5 整数双边滤波、双线性缩放。

当前显示裁剪源图上下各 32 行，将中间 256×192 区域缩放到 320×240。检测使用整张 RGB 图，但完全位于显示裁剪区域之外的候选不能作为可见框保留。

`pest_render_background()` 根据主画面边缘生成模糊镜像背景。显示去噪不改变检测使用的原始 RGB 数据。

### 4. PS 上传与坐标换算

`ps_app/main.c` 的 `pest_run()` 依次执行检测、显示渲染、背景生成、图像上传、框配置和串口输出。

- 主画面 320×240，由 PL 等比放大 3 倍为 960×720。
- HDMI 可见画面为 1280×720，两侧各 160 像素使用柔和背景填充。
- 主画面坐标到屏幕坐标：`screen_x = 3×display_x + 160`，`screen_y = 3×display_y`。
- PS 将图像写入 PL 图像缓存，将最多 8 个框写入坐标寄存器并提交配置。

### 5. PL 视频处理与输出

`system_top.v` 连接 PS、AXI 寄存器、图像缓存及视频流水线。`image_rom_src.v` 读取图像，`video_pipeline.v` 组织视频时序、滤波和标注。

PL 支持灰度、均值、高斯和 Sobel 模式。病斑演示默认切回灰度；框线在滤波后叠加，避免卷积把红框模糊。跨时钟域的框配置通过同步模块送到像素时钟域，最终通过 HDMI 输出。

### 6. 串口操作

串口参数为 COM7、115200、8 数据位、无校验、1 停止位。

| 命令 | 功能 |
|---|---|
| n / b | 下一张 / 上一张 |
| p | 重新检测当前图片 |
| o | 显示或隐藏红框 |
| s | 测试全部 24 张并输出混淆矩阵 |
| [ / ] | 调整棕色阈值 |
| m | 显示菜单 |
| 0 / 1 / 2 / 3 | 灰度 / 均值 / 高斯 / Sobel |
| h | 测量硬件视频帧率 |
| c | 运行软件滤波基线对比 |

## 三、开发、编译与验证流程

```text
检查原始 RGB 与输出框
    → 分析掩膜、候选及拒绝原因
    → 修改 PS C 算法或 PL RTL
    → 主机回归与图像对照
    → ARM 编译；若修改 RTL 则另外综合、实现、生成 bitstream
    → JTAG 下载 PL bitstream 和 PS ELF
    → 串口全样本测试
    → 实际屏幕检查漏框、误框和画面质量
```

当前 v1.7 检测程序复用 v1.5 显示 bitstream。只修改 PS 检测算法时，不需要重新综合 FPGA 硬件。

在项目根目录编译、部署当前 PS 程序：

```powershell
./tools/build_pest_app.ps1 -Version 1_7
./tools/verify_pest_board.ps1 -Version 1_7 -Sample 19
```

第二条命令会实际重新下载板卡，需要板卡连接和 COM7 未被其他终端占用。以上命令仅作为操作说明。

## 四、当前结果与边界

v1.7 在这 24 张开发样本上，主机及板卡复测结果一致：TP=11、TN=12、FP=0、FN=1，分类正确 23/24。15、19 已检出病斑，第 24 张仍未检出可靠病斑。最大单张检测耗时约 182 ms，不包括渲染、上传等完整流程耗时。

视频刷新与病斑检测是两种不同速率，不能把视频连续刷新描述成每帧完成一次病斑检测。这 24 张是参与过调试的开发样本，23/24 不能作为独立测试集准确率；分类正确也不代表每处病斑都被框出。

当前最多显示 8 个框，18、21 已达到上限。后续完整评价需要补充每张图的叶片及病斑位置标注，分别统计误框、漏框和定位覆盖，再决定增加框容量或升级检测方法。
